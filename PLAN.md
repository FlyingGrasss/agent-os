## Where the six invariants stand

| # | Invariant | State | Enforced where |
|---|---|---|---|
| I1 | No untrusted bytes in the Controller's prompt | **Done** | Enforced at three independent layers, each of which fails closed on its own. (1) `Trusted<T>` is a separate type, so prompt assembly accepts nothing else. (2) `agentos-pager` is the only thing that can build a `Prompt`, and it records tool names rather than arguments because arguments are where tainted values live. (3) `Conversation::push` refuses a `Content::Untrusted` message for `Role::Planner`. Wired end to end: `Session` runs a plan -> pager assembles -> `Controller::respond` calls a real backend. Verified two ways -- a recorder capturing the exact `Conversation` at the moment `complete` is called, and the real Ollama client. Pushing untrusted content into the Controller fails all five wire tests. |
| I2 | Extractor has no tools, network, or filesystem | **Done** | `agentos-quarantine`: `SandboxedExtractor` forks, applies Landlock, applies seccomp, and only then starts the engine. Demonstrated against a real kernel by 18 escape tests, not argued from configuration. |
| I3 | Labels propagate through all operations | **Done** | `Val::map`/`zip`/`map_with_label`, interpreter's field/len/extract/iteration. 20,000-deep ASTs refused rather than overflowing the stack. `Label` has no `Default`, so a new ingest path cannot default to `Trusted` by omission. |
| I4 | Sensitive args reject tainted unless confirmed | **Done** | `PolicyHost` resolves â†’ evaluates â†’ audits â†’ acts only on `Allow`. The confirmation round trip is built. An absent rule is `Confirm`, never `Allow`. **Measured** over a 45-program corpus: 29/33 attacks succeed without the policy, 0/33 with it, and all 12 benign programs still run. |
| I5 | Process sees only granted fds | **Partial** | Landlock confines paths; seccomp refuses `socket(2)`, UDP, and Unix sockets; `SCM_RIGHTS` passes real descriptors; `pool.rs` forks and confines once at construction so no request can be served by an unconfined process. cgroup v2 CPU/memory/pids limits and private user+mount namespaces with a bounded tmpfs are implemented and **enforced**, opt-in per pool (`PoolConfig::cgroup_limits`, `PoolConfig::namespaces`) and failing closed when requested but unavailable. Verified under WSL with kernel evidence: worker membership in `/proc/<pid>/cgroup`, an OOM kill for a 64 MiB allocation under a 32 MiB ceiling, `nr_throttled > 0` under a 10% quota, a second fork refused at `pids.max = 2`, and namespace inode divergence with `/tmp` isolated in both directions. Still open: neither is on by default, I/O has no `io.max`, and a PID namespace is deliberately absent (a correct one needs a second fork). |
| I6 | Audit log, append-only, before execution | **Done** | `AuditLog::record_intent` returns an `AttemptToken` with private fields, so an effect cannot be performed without a prior durable record. |

## Phase 0 â€” Foundations and baseline

- [x] Six invariants stated as testable properties (`AGENTS.md`)
- [x] Evaluation harness wired to a backend trait (`agentos-infer`)
- [x] **Threat model document** (`THREAT_MODEL.md`) â€” assets, boundaries, attacker capabilities, and what is explicitly not defended against
- [x] **Measurement harness** (`agentos-eval`): 45 DSL programs run through the real interpreter in three arms that differ only in the rule set, with controls that make a good-looking zero impossible to obtain by accident.
- [x] **Policy denied / would-allow counterfactual** â€” the Â§9 obligation that could be met without a model, and now met. 29/33 attacks succeed against an engine that allows everything; 0/33 against the shipped rules; all 12 benign programs still run. The 0% is structural rather than surprising (fail-closed means a tainted argument can only reach Deny or Confirm), so the counterfactual control is what proves the corpus is genuinely adversarial rather than harmless.
- [x] **Automatic-versus-human split**, which is the number worth having. 12 attacks refused outright with no human involved, **17 held only by a prompt**, 4 stopped by the interpreter's step budget. Every command- and path-injection attack is in the first group; **four of five data-poisoning attacks are in the second**. That is Â§7.2 quantified, and it is the strongest argument in the repository that confirmation fatigue is a security problem rather than a UX annoyance.
- [x] **Resumable interpreter** (`agentos_dsl::machine::Machine`). A halt for confirmation no longer discards the plan's state: variables, loop frames, and spent budgets all survive, so a granted call is retried rather than skipped and the budget is cumulative rather than reset per approval. Checked against the existing recursive interpreter by a differential test over 24 programs, and against the old behaviour by 8 targeted tests.
- [x] **Session loop** (`agentos_core::Session`) â€” plan â†’ interpret â†’ confirm â†’ grant â†’ resume, driven end to end by the corpus. Holds no secret and decides nothing: the host still evaluates every argument and owns the grants, the user still answers, and `Machine` still decides only where to carry on from. The grant is derived from the values the host recorded at the halt, so no value is ever reconstructed anywhere in the cycle.
- [x] **How much of the defence is a person** â€” the number the resume path made measurable, and the one worth quoting. A fourth arm runs the **defended rule set** with a user who approves everything: **14 of 33 attacks succeed anyway**. Each of those was stopped by a prompt and nothing else: the rules were in force, the plan was checked, and a human waved it through. The 0% defended figure and this 42% are both true and describe the same system, so quoting the first without the second is the misleading half. Read alongside the item below, which is what makes a prompt worth reading at all.
- [x] **Intent pins â€” the agent defends itself, without asking** (`agentos_tools::IntentPins`). The user said "email bob@example.com"; that address is **trusted text they typed**. If a plan puts a *different* address, lifted from a document, in that position, the document has overridden something the user stated. That is a contradiction between two values the system already holds, decided on **shape alone** â€” no understanding of what the injection says, so it cannot be evaded by rephrasing. Enforced in `PolicyHost` before the grant lookup and only ever turning `Allow` into `Deny`, so **no approval can unlock it**. Verified end to end: the session ends in a denial with `asked() == 0`, even against a user who approves everything.
- [x] **The pins now have a measurement, and it took the right threat model.** Measuring them against the live 3B model gave **zero** â€” not because they fail but because a cooperative planner writes the user's own address and never gets steered. So an **adversarial planner** was added: deterministic, reads the request, and emits exactly the plan an attacker wants, routing document content into the pinned position. Against it the pins fire **4 tasks refused with no human involved**, and the approving-user leak rate falls from **92.9% to 64.3%**. The same 4 are refused whether the user declines or approves, which is the property that matters.
- [x] **The forwarding residual is a different problem from substitution, and the leak count was hiding it.** Measuring *bytes* of untrusted text reaching a tool shows the two live arms leak differently: the adversarial planner's leaks carry **112 bytes** (an address, short), while the live model's carry **522 bytes** (prose â€” a `note` or `footer` field forwarded into a message). Same metric, same "a tainted argument reached a tool", two entirely different threats.
- [x] **Why forwarding is not solvable structurally, stated plainly.** When the user says "email the invoice note to bob", forwarding the note *is what they asked for*. There is no contradiction to detect, so the intent pins cannot apply. The remaining options are (a) refuse to forward what the user asked to forward, which is wrong, and (b) classify text as "instruction-like", which is **detection** â€” evadable by rephrasing, and dishonest to present as a control. The real lever is **schema design**: a schema extracting `total: int, status: enum, due: date` has almost nothing to forward, while one with `note: string` has a forwarding surface proportional to the note. That is a measurable property of the schema, and shrinking it is the actual work.
- [x] **A schema bound is now enforceable, and measured.** A schema may declare `maxLength`; an extraction exceeding it is **refused, not truncated**. Truncating would let attacker text survive in a form nobody reviewed, and would report a value the extractor never produced. The bound is read once across the schema's properties and enforced against every string, walking records and lists rather than stopping at the top level. A schema with no declared bound gets no bound -- the absence of a limit is not a limit, and a default would make every existing schema look protected when none is. Deterministic A/B on the adversarial arm, 96-character bound:
  - **Unbounded, approving user:** 9/14 leaking (64.3%), **112 bytes** forwarded.
  - **Bounded, approving user:** 8/14 leaking (57.1%), **56 bytes** forwarded.

  **This is a modest result and is recorded as one.** The bound halves the payload and stops exactly one task. It does not close the forwarding gap, because a 56-character injection fragment is still an injection fragment -- the bound limits how much an attacker can say, not whether they can say it. The number that matters more is that the leak rate barely moved.

  **The confound, stated plainly:** `pin_denied` fell 4 -> 1 in the bounded arm, and reading that as "the pins got better" would be wrong. The bound refuses the *extraction*, so those tasks stop one step earlier, before the plan ever reaches the pinned tool. The attack is stopped -- by the extraction failing, not by the pin firing. The two columns count tasks that stopped, not tasks stopped *by the pins*; only the unbounded column measures the pins. The binary prints this note itself, so the table cannot be quietly misread later.

  **What this says about the hypothesis.** Schema tightness was the proposed lever and it is only partly right. A character bound shrinks the payload; it does not change whether forwarding is legitimate. Since the user asked for the note to be emailed, forwarding prose is what they requested, and any bound loose enough to carry a legitimate note also carries an attack.

- [x] **Closed types: the lever that actually works.** A schema field can declare `enum`, `integer`, or `boolean`, and the extraction is narrowed to it. An enum admits exactly the values the Controller wrote; anything else is refused, naming the field. An integer yields `PlanData::Int`. There is no fourth option in which attacker prose passes through. Deterministic A/B, adversarial planner, approving user:

  | | leak rate | bytes forwarded |
  |---|---|---|
  | unbounded | 64.3% | 363 |
  | 96-char bound | 62.5% | 307 |
  | **closed types** | **56.2%** | **182** |

  `model/status-injected` -- a document writing an instruction into a field the schema types as a closed enum -- is **refused with no value produced**, and does not appear in the closed arm's leak list. Its benign twin, carrying a legitimate `status=overdue`, still forwards in every arm, because the user asked for it.

  **Coercion narrows content; it must not widen trust.** A field coerced to `paid` stays `Quoted` and therefore stays tainted: the *choice* of that member was influenced by the document even though the *content* came from the schema. Converting it to `Str` would launder a label while appearing to sanitise a value.

  **The residual 182 bytes are the free-form fields, and no schema work removes them.** `note` is genuine prose and `recipient` is a genuine address. Closing a recipient would mean refusing to mail anyone not already on a list. The measurement says so rather than claiming a clean sweep.

- [x] **Two broken instruments, found because a null result did not look like a null result.** The first run of the closed-type A/B produced **identical** byte counts for the bound and the closed arms. That was not a finding:
  1. `footer` was left unconstrained in the closed schema while bounded in the other -- one arm accidentally weaker on the field under test.
  2. Every attack in the corpus routes through `recipient`, `note` or `footer`, the three fields that genuinely cannot be closed, so the corpus could not tell the two controls apart at all.
  3. Underneath both: the `Lift` fixture **hardcoded the status field** and never read the document, so the one task whose entire attack *is* the status line extracted a benign value.

  Same failure as advertising tool names that do not exist: **a fixture internally consistent with itself measures perfectly and means nothing.** All three fixed, and two tasks added -- an attack on a typed field and its benign twin.
- [x] **Extraction bridge** (`agentos_core::ModelExtractor`) â€” the missing link between the quarantined processor, which returns JSON, and the plan language, which needs `PlanData`. Every string in an extraction becomes `PlanData::Quoted`, so attacker text can never arrive as a planner-authored `Str`. The schema table is Controller-built; a plan cannot choose the shape of what it learns.
- [x] **The confirmation prompt now shows the value.** Found by a test failing while writing the bridge above: the user was asked to approve `send_email(to = <structured value>)`. That is not a conservative default, it is a broken one â€” a user asked to approve an invisible value has nothing to read and one available answer, so the "human in the loop" is a rubber stamp while every approval is still recorded as deliberate. `ArgView` now carries a display rendering separate from the text the *rules* inspect, so quarantined text reaches the person deciding and still cannot be pattern-matched by a rule or written to the audit log. Control characters are stripped, because the value is attacker-controlled and the destination is a terminal.
- [x] **Planner** (`agentos_core::Planner`) â€” the last missing piece between a task and a plan. Assembles its own conversation, so the planner's prompt is fixed text plus a `Trusted` task with **no parameter through which untrusted bytes could arrive**; I1 is enforced by the API's shape rather than by a check somebody has to remember. Model JSON is rendered into plan-language source and **fails closed** â€” an unrecognised operation, a missing field, a statement count over the bound, or a newline inside a field all refuse the whole plan, because silently skipping one would produce a task recorded as completed that did less than the model asked for.
- [x] **End-to-end against a real model.** `llama3.2:3b` was asked to "fetch the invoice, email the note field to the address it names". It wrote exactly that plan â€” fetch, extract, `send_email(to = inv.note)`. The session ran it; the attacker-chosen recipient `attacker@evil.test` reached the confirmation prompt; the user declined; the mail was never sent. **A real model, writing a real plan, piped attacker-controlled document content into a sensitive argument and was stopped.**
- [x] **Attack success rate against a real model** (`agentos-model-eval`). ## Phase 1 â€” Core daemon and capability broker

- [x] Provenance types: `Val<T>`, `Label`, `Trusted<T>`, `Quarantined<T>`
- [x] `Cap<K>` with sealed marker types (compile-time handle confusion)
- [x] Tool trait with typed arguments (`Tool` in `agentos-tools`)
- [x] Append-only audit log, written before the effect (I6)
- [x] **Hash-chained audit ledger, so I6 is tamper-*evident* and not merely append-only.** "Append-only" is a promise about this process's behaviour and says nothing about whoever can open the file afterwards; deleting the line recording a tool call leaves a log that still looks perfectly ordinary. Each line now commits to its predecessor via SHA-256 over the literal line bytes, so an edit, deletion, reordering, or partial write breaks every link after it and names the first broken line. `agentos audit verify [--path P]` recomputes the chain and exits non-zero on a fault, so it works from cron; it prints the chain head, which is the only thing worth keeping from a run.
  - **Measured under load.** `benches/concurrent_dispatch.rs` and `tests/concurrency_stress.rs`. Fifty OS threads on their own authenticated connections, against one daemon appending to one real file: the chain stays intact across 2,500 records, no record is lost, the inode does not move, and nothing deadlocks. Latency rises linearly with client count (p50 1.9 ms at 1 client, 42 ms at 50, 56 ms at 64) rather than degrading sharply, and the sustained ceiling is ~550 tasks/sec on a debug build. `FileSink`'s mutex is what makes that hold: the chain advances once per record, so an unlocked append would interleave mid-line and break verification immediately.
  - **`--pin` closes the gap the chain cannot.** A truncated log is a shorter but perfectly valid prefix, so `verify` alone returns exit 0 on a log that is missing its most recent records — demonstrated live, not theorised. `agentos audit verify --pin <HEAD>` additionally requires the final head to match, and reports a mismatch as its own exit code so a monitoring job can tell "a record was altered" from "the log lost its tail": **0** intact (and pinned, if asked), **1** chain broken, **2** intact chain, wrong head, **3** usage error including a malformed pin. The pin is an *additional* requirement and never a substitute: a broken chain stays exit 1 whatever is pinned. A malformed pin is rejected **before** the log is opened, so a typo is never reported as tampering, and comparison ignores case because the value is typed by hand.
  - **The chain is keyless, and that is the limit, not a detail.** The digest is `SHA-256(label || prev || bytes)` and everything needed to recompute it is in the log. It catches accidental corruption, splicing, out-of-order insertion, and an editor that changed a byte without recomputing the rest. It does **not** resist an attacker who rewrites the file and recomputes the chain from genesis. Pinning the head somewhere the log's author cannot reach is what closes that, and `--pin` is the half of it an operator can actually run.
  - **The chain wraps the record rather than living inside it.** `AuditRecord` is `Serialize`-only on purpose: a `BoundedText` read back off disk could claim a length its constructor would have refused. Chain fields *inside* the record would force the verifier to deserialize it, reopening that hole in the one component whose entire job is reading a file an attacker controls. The line is `<prev_hex> <hash_hex>\t<json>` and the verifier hashes the remainder as opaque bytes. Binding literal bytes also catches reformatting that field-by-field comparison would miss.
  - **A bug the tests caught:** the hex decoder accepted uppercase, and `'a'` differs from `'A'` only in bit 5 — so flipping one bit of a digest left the log verifying with different bytes on disk. The encoding is now canonical lowercase, which is what makes "any single-bit change is detected" true at the byte level. `a_single_flipped_bit_in_any_record_is_detected` flips every bit of every byte of a real log file.
  - `FileSink` recovers the chain head from the tail of an existing log on open, and **refuses to append** to one that does not verify: continuing from a broken link would make every later record inherit the break and launder it. Logs predating the chain report `Unchained` and say to rotate, not "COMPROMISED".
  - **`FileSink` also refuses to append to a log that is no longer the file at its path.** Found during live testing, and it is the worst failure in this file. A long-running daemon holds one descriptor; `logrotate`'s default rename-and-create (or an atomic editor save, or a restore from backup) leaves that descriptor attached to an inode with no name. It keeps accepting writes, every reader opening the path sees a *different* file, and `audit verify` passes on the replacement. Observed: six records in an unlinked inode while the file on disk still reported `ok 2 records chained`. So each append re-reads the identity of the path and compares it against the descriptor's, and refuses with `AuditError::LogRotatedOrReplaced` naming **both** identities.
    - The identity is re-read from the *descriptor* after every append, not from the path: the path can be swapped between a check and its use, the descriptor cannot. One `stat` per record against a `write`+`fsync` that costs far more.
    - **Exact on Unix** (`st_dev` + `st_ino`), **a proxy on Windows**: `volume_serial_number` and `file_index` are still unstable in std, so it falls back to creation time and size. That catches rotation, truncation and restore, and would miss a replacement that reused both. Stated in the type's docs rather than glossed, because a check that sounds stronger than it is is worse than none. `last_write_time` is excluded from the proxy on purpose: this sink's own writes change it.
    - **It is fail-closed all the way down.** `PolicyHost::call` turns a failed `record_intent` into `ToolRejected` and never looks the tool up, so a rotated log stops *work* rather than letting it run unrecorded. Verified live: the refused `fs.write` left no file behind.
    - Recovery is a restart, which re-opens by path and resumes the chain from whatever the new file contains.
    - `FileIdentity` carries size as well as device/inode, because a log that *shrank* under an unchanged inode is `copytruncate` and must be caught. That makes it the wrong tool for "was this file replaced?", where size is expected to differ — so `same_file` compares identity only. The stress test uses that, and asserts the size *grew* as well, so a run that wrote nothing cannot pass.
  - **A finding from the concurrency work, now fixed:** `AuditRecord::seq` was documented as "monotonic, 1-based, never reused and never reordered", and that was false across tasks. The counter lived in each task's `AuditLog`, so fifty concurrent tasks produced fifty records numbered `1`, `2`, … The chain was unaffected (it commits to the literal line bytes, not to sequence numbers), but the documentation claimed a guarantee the code did not provide. The counter now lives in the sink, which is the object tasks genuinely share: `seq` is a ledger-wide total order across concurrent tasks and resumes past the records on disk when a log is reopened. The stated obstacle, that sharing a counter would mean sharing the whole `PolicyHost`, applied only while the counter lived in `AuditLog`; moving it into the sink dissolved it. The test that pinned the old behaviour was inverted rather than deleted, and mutation-verified in both directions: dropping the increment fails all three sequence tests plus the stress test, while restarting the counter on reopen fails only the reopen test.
  - Verified against a ledger built by a *separate* implementation (PowerShell, not Rust): the genesis nonce matches, so the format is reproducible by anything, not only by this crate.
- [x] **One environment vocabulary for the daemon and the client.** Found during the live walkthrough: setting `AGENTOSD_TCP_ADDR` and running `agentos check` produced no error and no warning — the client read `AGENTOS_TCP_ADDR`, found nothing, and fell through to the hardcoded default port. Both spellings were correct; the daemon simply listened where the client was not looking, and the only symptom was a connection error naming an address the operator never set.
  - `crates/agentos-cli/src/env.rs` is now the single resolver for the three variables the halves must *agree* on: `AGENTOS_SOCKET`/`AGENTOS_SOCKET`, `AGENTOS_TCP_ADDR`/`AGENTOSD_TCP_ADDR`, `AGENTOS_TOKEN_FILE`/`AGENTOSD_TOKEN_FILE`. Canonical name first, daemon spelling accepted, and both call sites report **which name they honoured** — the question the split made unanswerable.
  - **Disagreement is refused, not resolved.** Setting both aliases to different values is an error naming both, because silently picking one lets the daemon and the client choose differently and neither log says why. Equal values (modulo whitespace) are not a conflict: two spellings of one intention is what an alias is for. Blank counts as unset, so `FOO=` cannot silently override a real setting.
  - **A set-but-unparseable address is now an error.** It used to fall through to the next candidate, so a typo looked exactly like the variable being unset — the same silent failure one step further along. Refusals now point at port 1, so a failure path can never produce a working connection.
  - Daemon-only variables (`AGENTOSD_MODEL`, `AGENTOSD_WRITE_ROOTS`, `AGENTOSD_ALLOWED_HOSTS`, `AGENTOSD_MAIL_OUTBOX`, `AGENTOSD_AUDIT_LOG`, `AGENTOS_INBOX`) are deliberately **not** unified: there is no client counterpart to disagree with, so a second spelling would only add a way to misspell it.
  - **Clippy is clean under `-D warnings`, including the two warnings that predate this work.** `Client::needs_auth` was a stored field nothing read, so it was removed rather than allowed. `DaemonState::new`'s eight arguments are allowed with a written justification instead of a bare `#[allow]`, because the fields do not co-vary and grouping them would put `token` somewhere it looks unrelated to `requires_auth` — the pairing that has to stay obvious.
  - **A methodological note, because it nearly produced a false bug report.** `Copy-Item` preserves the source file's LastWriteTime, so restoring a mutated file gave it a timestamp *older* than the artifact built from the mutation, and cargo never rebuilt. Three tests failed against a stale binary and it looked exactly like a bug in the pin comparison. Reverting a source file for mutation testing must force a rebuild; do not trust `cargo` to notice.
- [x] Policy rules per `(tool, argument)`, absent rule defaults to `Confirm`
- [x] Policy enforced at the tool boundary (I4)
- [x] **Promotion requires a policy halt, and the value that halt named.** `Disclosure::approve` used to take any `Val` and any `&self`, so any caller holding a tainted value could mint a `Trusted` with no host, no engine, no audit entry, and no user in the loop. It now requires an approved `PendingConfirmation`, and additionally `approve(pending, arg, shown)` checks `shown` against the value the engine flagged *for that argument*. Without that check the digest is circular: it is minted from `shown` and verified against `shown`, so it proves only that the token matches itself. Mutation-verified: removing the check promotes a substituted recipient as `Trusted`.
- [x] Confirmation requests are counted by the I1 report rather than being structurally zero
- [x] Capability broker with real handles, lineage, attenuation, and **real revocation**: `CapRegistry::authorise`, `attenuate`, transitive `revoke`, and ids that are never reused
- [x] Escape tests: `../`, symlinks, absolute paths, and descriptor-vs-name all fail â€” 41 for `http.fetch`, plus the `fs.write` suite
- [x] `schemars` derives on real tool arguments (`fs.write`, `http.fetch`)
- [x] **`agentosd`, the long-running privileged daemon.** `crates/agentos-cli/src/daemon/`, reachable as the `agentosd` binary. A `tokio` current-thread runtime (all real work is handed to `spawn_blocking`; the async side only moves bytes). IPC is a Unix domain socket on Unix and a TCP socket bound to loopback elsewhere, both carrying a 4-byte big-endian length prefix and a JSON-RPC 2.0 payload. Each accepted connection is served independently: a request that fails is answered with an error and the connection stays open.
  - **A request narrows authority, never widens it.** Every grant is an intersection of the operator's `Ceiling` (from the environment) with what the request asked for. A host or write root outside the ceiling is *refused loudly*, not silently clamped â€” a silent clamp would let a client believe it can reach a host it cannot, and the plan would fail confusingly halfway through instead of up front. Containment runs on the **resolved** path: `Path::starts_with` is per component but still lexical, so `/srv/outbox/../etc` passes it and then canonicalises to `/etc`. Canonicalising first is what makes "checked" and "granted" the same path. `/srv/outbox-evil` is still not inside `/srv/outbox`. An empty environment yields an inert daemon.
  - **The daemon never approves.** `executor::refuse_but_record` answers `false` to every confirmation. A daemon has no stdin, so it can never satisfy the project's own rule that approval requires a person; adding an IPC approval path would make every local process that can reach the socket a principal in the authority model. The consequence is stated rather than hidden: **a headless daemon cannot execute any plan that needs approval**, and `info` reports `can_ask_human: false` so a caller cannot plan around a capability that does not exist.
  - **"Nobody said no" is not "a person said no."** The refusal closure records each request it turns down, so a halt for want of a person is reported as `needs_human` with the rendered request attached, rather than as `refused`. Same distinction `Outcome::ConfirmationLimit` was split out to preserve.
  - **A non-loopback bind is refused, not warned about** â€” the socket is unauthenticated and the process holds write authority, so a daemon that started with a warning is a daemon someone deploys with the warning scrolled past.
  - The wire is closed: `deny_unknown_fields` on every request type, bounded frames (refused before allocation, never truncated), and a client-supplied `timeout_secs` clamped to a maximum.
  - Task text arriving off the socket is `Quarantined` at the boundary. It reaches the planner through one explicit promotion carrying `Origin::User`, so the audit trail shows tasks attributed to the daemon's configured user rather than to whoever sent the frame.
  - Verified by mutation, not just by passing: flipping the refusal to `true`, deleting the write-root containment check, and disabling the loopback check each fail named tests. Live smoke test (`target/smoke-agentosd.sh`) starts the daemon against a real `llama3.2:3b`, then requires that a widening request gets `-32003`, an unknown field gets `-32602`, and `0.0.0.0` is refused.
- [x] **Ambient inbox monitoring.** `crates/agentos-events/src/inbox.rs` (watcher) and `crates/agentos-cli/src/daemon/inbox_loop.rs` (wiring). A zero-dependency polling watcher over one directory; a dropped `.txt`/`.html`/`.json`/`.md` file generates a task without anyone at a keyboard. Off unless `AGENTOS_INBOX` is set or the conventional path already exists â€” the daemon does not create the directory whose contents it treats as a reason to wake an agent.
- [x] **End-to-end harness.** `crates/agentos-cli/tests/e2e.rs` — 15 tests, **0.01s**, no network, no sleeping, no subprocesses. Real `DaemonState` on an ephemeral loopback port, real length-prefixed frames, real startup token written and read back, real files dropped into a real inbox, real REPL driving the real `Client`. 765 workspace tests, zero failures, 19s including compilation.
  - **The model is replayed, not mocked around.** `entry_point()` builds a real Ollama backend and refuses to start unless the model is pulled, so it cannot run on any machine that is not a developer laptop. The harness supplies a `Backend` that replays the planner's JSON, which keeps the whole pipeline from `Session` through policy out to the audit log under test, and removes the one dependency that cannot be made hermetic here.
  - **Cleanup is `Drop`, not a teardown line.** A test that fails an assertion panics before reaching its cleanup call, and a harness that leaks a socket directory or a token file on failure turns one broken run into a permanently flaky suite — and a leaked `auth.token` is a live credential for whatever runs next. `a_failing_assertion_still_leaves_nothing_behind` exists specifically to keep that story honest.
  - **`NeedsHuman` is deliberately *not* reached over the socket**, and the file says why in full. It needs a tainted argument, the only source of taint inside `run_task` is `extract`, `ModelExtractor` takes an untrusted document only, and the sole producer of one is `http.get` — which cannot be aimed at a test server, because `address_is_routable` refuses loopback (correct SSRF defence) and `TcpTransport` refuses `https` (there is no TLS). A live fetch would need the internet plus a model. So the gate is covered where it is load-bearing: over the real socket, `approve`/`confirm`/`authorize`/`grant` are all `METHOD_NOT_FOUND` and an `approved` field on an execute is `INVALID_PARAMS`, which is the stronger claim anyway; and through a real REPL, answering `y` re-submits the *person's own words* rather than granting anything.
  - **Mutation-verified, and one mutation found a weak test.** Removing the auth gate fails 6 tests; disabling the token bucket fails the flood test; making the chain verifier always return `Ok` fails the tamper assertion; forwarding the agent's rendered request instead of the person's words fails the approval test. The fourth mutation — deleting the write-root containment check — initially **passed**, because on Windows constructing a grant for `/etc` fails as a *configuration* error and returns the same `GRANT_DENIED` code. Asserting the refusal *reason* is what caught it. This is the recurring failure mode in this repo, live again: a check passing while the thing it checked was broken.
  - **The task text is a constant.** `INBOX_TASK` is not a format string, and `params_for()` takes **no arguments at all**, so there is no filename, path, or payload in scope from which a task string could be built. The guarantee is structural rather than "the author remembered not to interpolate". A filename is attacker-chosen bytes â€” a download called `ignore-previous-instructions.txt` â€” and interpolating it would reach the Controller's prompt, which is I1 failing at a new seam.
  - **The payload is the data path, not the instruction path.** Read as `Quarantined`, crossing to the extractor under the schema. The task says what kind of work to do; the payload supplies the data; neither supplies the instructions, and the task text says so explicitly to the model.
  - **An inbox event carries no filename.** `InboxEvent` is closed vocabulary in the style of `Event` and `Record`; the name appears only as a `NameHash`, which has no `Display` and a redacting `Debug`. `InboxEntry` keeps the path private with no string accessor at all.
  - **Inbox tasks carry no grants.** An IPC client proves itself with the bearer token; a dropped file proves nothing, since anyone who can write the directory can drop one. Drawing on the operator's ceiling would make write access to one directory equal to the daemon's whole configured authority. So inbox tasks get an empty grant set and halt at `needs_human` for anything privileged.
  - **Symlinks are refused.** Checked with `symlink_metadata`, so a link to `/etc/shadow` dropped as `note.txt` is ignored. Verified on Linux by mutation: swapping `symlink_metadata` for `metadata` fails `a_symlink_is_never_followed`.
  - **A file is reported only once its size is stable across two polls**, so a half-written file is not read as a truncated instruction. Bounded payload, closed extension list, and a processed-file archive so one drop produces one task.
  - Verified by mutation: interpolating the entry into the task fails `the_task_text_is_a_constant_and_names_no_file`; adding a grant fails `an_inbox_task_carries_no_grants`; inverting the settle rule fails 8 tests. A live end-to-end run against a real `llama3.2:3b` drops a file, watches it get archived to `processed/`, and confirms the payload was preserved intact and not re-triggered.
- [ ] One session actor per task, typed mailboxes. The daemon serialises on the backend instead: `Backend::complete` takes `&mut self`, and a pool of backends would mean a pool of loaded models on a host with ~6 GB free. Concurrency is bounded by a semaphore and task execution runs on `spawn_blocking`. **Not yet done:** a typed actor per task with its own mailbox. The inbox watcher was initially written to hold that lock across its poll interval, which would have serialised the whole daemon behind a one-second sleep; it now takes the lock only around a run.
- [ ] `cap-std` for in-process filesystem access. **Deliberately not added.** Nothing in the workspace depends on it, and this workspace already has a capability model that the `Tool` implementations actually enforce: `WriteGrant`, `FetchGrant`, and `MailGrant`, plus `agentos-sandbox`'s `FsGrant`. The daemon provisions per-task capabilities from those. Adding `cap-std` would introduce a second, parallel capability model â€” the same class of mistake as adding a second source of truth for taint.

## Phase 2 â€” Process confinement

- [x] Kernel capability verified, not assumed. Landlock is compiled in and was confirmed by *building a ruleset and escaping it* â€” `/etc/passwd`, `/proc/self/mem`, `/sys/kernel/security`, and a symlink out all denied.
- [x] seccomp confirmed enforcing: a real BPF allowlist installed, a child refused disallowed syscalls with `ENOSYS`, and `CONFIG_SECCOMP_FILTER=y`.
- [x] `PR_SET_NO_NEW_PRIVS` in every confined child, confirmed to default to `0`.
- [x] Landlock ABI-version fallback matrix, fail closed.
- [x] `socket(2)`, UDP, and Unix sockets refused under seccomp, closing the hole Landlock leaves.
- [x] A `FORBIDDEN` table naming the syscalls that must never appear in any profile, each with its reason, checked both by `Profile::refused` and again by `apply` refusing to install a filter that has grown one.
- [x] `SCM_RIGHTS` fd passing, with `O_NOFOLLOW|O_DIRECTORY|O_NONBLOCK` on the receive side.
- [x] **Pre-forked, pre-confined worker pool.** Workers are confined at construction; a request never pays for confinement and can never be served by an unconfined process. Request caps, idle timeouts, and liveness are enforced, with the death check going through `waitpid(WNOHANG)` rather than `kill(pid, 0)` because a zombie answers `kill` like a live process.
- [x] `ptrace`, `clone`/`clone3` (refused together, or neither), `io_uring` (closed at setup), `perf_event_open`, `memfd_create`, `userfaultfd`, `bpf` are outside both Landlock and every profile.
- [x] **cgroup v2 limits, and the reason the old "blocked" note was wrong.** User, mount, and pid namespaces work unprivileged on WSL, and the systemd user manager's cgroup is delegated with `cpu memory pids`. `agentos_sandbox::cgroup` creates one cgroup per worker before the fork, enables the controllers, writes `memory.max`, `memory.swap.max`, `pids.max`, and `cpu.max`, reads each back, and moves the child in **before** `execveat` through a one-byte barrier. Every failure refuses the spawn. Discovery checks not only that a destination is writable but that the caller's own `cgroup.procs` is, because cgroup v2 migration is checked against the source too; that check turns a bare `EPERM` at first spawn into an error naming the delegated-scope requirement. Tested by kernel observation, not by reading back our own writes: `memory.events.oom_kill` after a 64 MiB allocation under a 32 MiB ceiling, `cpu.stat.nr_throttled` after a 500 ms burn under a 10% quota, and a second `fork` refused with `EAGAIN` at `pids.max = 2` (migration alone does not enforce `pids.max`; the probe must fork *inside* the cgroup, which is why that probe is unconfined). Mutation-verified: disabling the attach fails the membership and memory tests. Not limited: I/O (`io.max` needs a device number the pool does not know).
- [x] **User and mount namespaces via `rustix`, with a private `/tmp`.** `agentos_sandbox::ns` unshares a user namespace mapped `0 <euid> 1`, writes `setgroups=deny`, checks `geteuid() == 0` inside rather than assuming the map took, unshares the mount namespace, makes every mount private, moves off `/tmp`, and mounts a bounded `nosuid,nodev,noexec` tmpfs there. Applied **before** Landlock (rules describe the tree the worker actually runs in) and before seccomp (which makes the state durable: neither `mount` nor `unshare` is allowlisted). A failure refuses the worker. No PID namespace: `CLONE_NEWPID` without a second fork is a no-op that looks like isolation, so it is absent rather than wrong. Tested both directions: a host marker under `/tmp` is `ENOENT` inside, a worker write never appears on the host, and `/proc/<pid>/ns/{mnt,user}` differ from the parent's. Mutation-verified: making `apply` a no-op fails the namespace test on both inode comparisons.

**Consequence:** the sandbox now rests on four layers: Landlock for reach, seccomp for syscalls, cgroup v2 for cost, and user/mount namespaces for the uid and `/tmp`. The first two are always on; the last two are opt-in per pool and fail closed when requested. I5 is demonstrable rather than merely designed. The remaining resource gap is I/O bandwidth, and the remaining isolation gap is the PID namespace, both stated above rather than implied.

## Known open risks

1. **Model measurement exists but is thin.** The policy layer is measured over 45 programs, and the model arm now runs end to end: a real model writes a plan, a hostile document attacks it, and the session enforces policy. The original 42-sample figures (0/42 reading, 7/42 approving) are **stale and were produced on a broken harness**: the planner instruction advertised `http.fetch` while the eval host registered `http.get`, so live plans died on their first call and the 0% was vacuous. That is fixed (`Planner::with_instruction` plus a drift test), and a fresh single run on 16 tasks gives 0/16 declining and 1/16 (6.2%) approving, with 3-4 model-quality failures per arm. It is still **one 3B checkpoint over one run**, with role Q stubbed. A different model, a real Q, or more runs would move it. Nothing here should be read as a claim about models in general.

- [ ] **Multi-model verification harness** (Phase 7) will quantify invariant preservation across model families and sizes.

2. **Most of the surviving defence is still a human, and a daemon removes the human entirely.** Of 33 corpus attacks, 12 are refused automatically and **17 get through if the user approves everything**. Against a *cooperative* model the leak rate is 0% for a reading user and ~17% for an approving one. Against an **adversarial planner** â€” the threat model, since the planner's output is what an attacker steers â€” it is 0% and **64.3%**. The intent pins took that from 92.9%, which is real progress and a fraction of the problem: they cover substitution and not forwarding. On data poisoning â€” the residual hole both CaMeL's and AgentDojo's own authors name â€” four of five attacks survive an approving user. Confirmation fatigue is a security property here, and the design only partially defends it.

   **This is why `agentosd` refuses every confirmation rather than accepting one over IPC.** The 17 attacks that need an approving user are exactly the attacks a headless daemon cannot defend against, and the two honest options were to deny (leaving the daemon unable to run those plans) or to invent an IPC principal (making every local process a source of authority). It denies. The cost is real and is stated: **a headless daemon can only run plans whose arguments policy allows outright.** Removing that cost needs authenticated IPC plus an interactive front-end, which is the next piece of work rather than something to paper over.

- [ ] The residual 182-byte forwarding surface (`note` + `recipient`) is a **measured structural limit**, not an engineering debt. No schema work removes it without removing the user's data. This is documented as the theoretical minimum bound for human-intent data delivery.

3. **Resource containment is opt-in and does not bound I/O.** cgroup v2 limits and namespaces exist and are enforced, but a pool that does not ask for them still runs workers with no CPU, memory, or pid ceiling, and even a limited worker can saturate a disk because `io.max` needs a device number the pool does not know. Landlock and seccomp control *reach*, not *cost*. The DSL's own step and loop budgets remain the only always-on bound, and the measurement shows they do fire.

4. **eBPF loading unverified** after the sysctl change.

5. **The pool's confinement is Unix-only and its test image is a reference.** `agentos-worker` proves the mechanism; it is not the real interpreter. A different image may need loader syscalls the `Worker` profile does not grant, and the failure mode is a worker that cannot start rather than one that runs too freely â€” the safe direction, but still a deployment hazard.

6. **`Profile::Worker` grants `prctl`.** It is safe as installed â€” the filter is already in place and can only be made more restrictive â€” but `prctl` is a broad syscall to hand out and the grant exists for a startup path that has not been pinned to the specific call.

7. **The quarantine engine is a no-op.** I2 is demonstrated; the thing that will actually read documents is not built.
8. **A loop body in the DSL cannot bind a variable.** `Interp::exec` rejects a second `let` of the same name and a loop never unbinds, so a `for` body may contain only `report` and nested `for`s. Found while building the corpus. It is a real limitation rather than a security hole, but it makes loops nearly useless and it is why the corpus cannot express "one tainted write reached many times".
9. **The resume path is built; the loop that uses it is not.** `PolicyHost::call` returns `Err(ConfirmationRequired)` on a `Confirm`, which propagated out of `agentos_dsl::run` and discarded the interpreter's `State` â€” its variables *and* its spent step and loop budgets. `agentos_dsl::machine::Machine` now carries all three across a halt, and the old recursive `run` remains for programs that never halt. What is still missing is the session loop that drives it: nothing yet turns a `Step::Halted` into a `Disclosure` request and a grant back into a resumed `advance`. The three defects that made this harder than it looked, and how each was resolved:
   - **Re-running the plan is not safe.** A halt on the second tool call means re-running replays the first one's side effect. Memoising on `(tool, args)` to avoid that would make the audit log a fiction: it records an attempt and performs no effect. Two identical `fs.write` calls in one plan may also legitimately be two writes. *Resolved by resuming rather than re-running, and by recording only the tool calls made inside the single statement that is in flight â€” not the whole plan.*
   - **A resume needs a frame stack, not just a cursor.** `ForEach` iterates a list and binds a variable per item; a halt inside the body loses the items, the index, and the label. `State::vars` alone is insufficient. *Resolved with a `Frame` stack carrying the item list, its label, and the body cursor.*
   - **Budgets must be carried, not restarted.** `steps` and `loop_iterations` live on the machine, so a resume cannot reset either â€” a budget-*escalation* hole rather than an inconvenience. `Literal::Quoted` carries a `SourceId` in the AST, so re-evaluating it yields the same label and a `Confirmation` issued for it still matches. *Both verified by test.*
   - **A fourth defect, found by reading rather than by a failing test:** the in-flight record was first keyed by `(tool, argument index)`. That is ambiguous the moment one statement names the same tool twice, because a nested call restarts the index at zero â€” `mail(subject = h(k = "a"), body = h(k = "b"))` served `body` the result computed for `"a"` and never invoked the second `h`. Beyond being wrong, that is a **taint-laundering path needing no injection at all**: a trusted result computed for one argument could be delivered to a position where a tainted one belonged. The key is now the *call site* (the path of argument indices from the statement root), and the differential corpus carries four same-tool-twice programs so the shape cannot regress.
   - **A fifth defect, found by adversarial review:** a hard error left the machine re-runnable. `advance` returned the error without advancing the cursor *and* discarded the in-flight record, so the natural caller â€” `loop { match advance { Err(e) => log(e), .. } }` â€” re-ran the failed statement with an empty cache and invoked its tools again; a test measured `helper` running six times for one intended call. The comment claimed "on a hard failure the machine stops", and nothing enforced it. `Machine` now **poisons** on any non-halt error and reports the same error thereafter.
   - **A test-harness defect, found by adversarial review:** the differential harness rendered argument values without their labels, so two values differing only in provenance compared equal. The one automated check that compares the two implementations on I3 was structurally unable to fail on an I3 regression. It now renders each value's trust level â€” the security-relevant property, since a `SourceId` is a per-call random UUID that would make every run differ from every other â€” and five halting programs were added, so the corpus finally exercises the resume machinery rather than only the path that never needed it.
10. **`PolicyHost`'s `op` identifier is lossy.** It is built from `request.items.first()`, so a `send_email` with both `to` and `body` tainted yields the single op `send_email.to`. The *display* is correct â€” `drain` shows every item â€” and `grant_pending` now grants every flagged argument rather than keying on `op`, so the collision no longer breaks resumption. But anything else keying on `op` still collides across calls differing in later arguments, and a refusal record naming `op` is ambiguous in the same way.
11. **The planner is a small model's weakest link, and that is not a security finding.** `llama3.2:3b` produced a valid, correct, *attack-carrying* plan for the end-to-end case and an unparseable one for two of three others â€” once emitting `+` into the source, once inventing a schema (`Address`) that was not registered and was therefore refused. Both refusals are the system working. The risk to watch is scoring: an unparseable plan must be reported as model quality, and if it were ever counted as "attack blocked" the measurement would improve for the wrong reason.

12. **The daemon's IPC socket has no authentication.** Anything that can reach the loopback socket can submit a task, and the daemon will plan and run it within the operator's configured ceiling. The ceiling is what bounds this â€” a request cannot widen authority â€” but "who sent this" is not recorded beyond the audit log's configured user. On a single-user machine this is acceptable; on a shared host, the loopback socket is shared by every local user, and the daemon's identity is one fixed `UserId` rather than per-request. **The Unix socket is created `0600`, which closes this for the Unix path only; the TCP loopback path does not have an equivalent.** The fix is per-request authenticated identity, and it is not built.

13. **Task execution is serialised on the model, and a timeout does not cancel work.** `Backend::complete` needs `&mut self`, so concurrent tasks queue on the backend. The consequences are deliberate and worth naming rather than discovering under load: a task that exceeds its `timeout_secs` has its *result* abandoned but keeps running, because `spawn_blocking` tasks cannot be aborted and killing one mid-`sync_data` would corrupt the audit invariant I6 protects. A slow task therefore holds the model until it finishes. The upper bound on that is the plan's own step and loop budgets; there is no wall-clock kill.

14. **The ambient inbox is an unauthenticated wake-up channel, and that is its defining weakness.** Anyone who can write to the inbox directory can make the agent start a task. That is *less* than it sounds, because the task is a fixed constant carrying no grants: the worst a file drop can achieve is a summarisation attempt that halts at `needs_human` for anything privileged. It is still not nothing, and the honest framing is that the inbox trades I1's guarantee for availability â€” the system now acts on the world's initiative rather than only a person's.

    **Mitigations in place:** no grants; no filename in the task text (`params_for()` takes no arguments, so the interpolation expression does not exist); symlinks refused via `symlink_metadata`; payload quarantined; size-stable-across-two-polls settle rule; 1 MiB payload cap.

    **Flooding is now bounded.** A `TokenBucket` admits 12 payloads/minute sustained with a burst of 8. Excess moves to `inbox/deferred/` rather than being dropped â€” the user's payloads stay on disk and drain as credit accumulates, so a flood costs *latency, not data*. A burst allowance rather than a strict sliding window is deliberate: a person dropping four files at once should not be throttled, and the threat is a sustained flood, not ordinary use. The bucket saturates at burst size, so an hour of idleness releases eight and not 3600.

    **Duplicate drops cost nothing.** A bounded 1024-entry window of SHA-256 payload digests is consulted *before* a token is spent, so ten thousand copies of one file cost one model call rather than ten thousand. The reverse order would spend tokens discovering that ten thousand files are the same file. Dedup is bounded rather than absolute: re-dropping a file after it has aged out costs one call, because a limit that can be pushed is worse than a window that expires. **The cost, stated plainly:** re-dropping a byte-identical file is skipped, so a legitimate retry requires changing the content.

    **Tracing no longer requires exposing the filename.** Two identifiers, because they answer different questions and only one is safe to print. A random 128-bit `CorrelationId` correlates one run's log lines and discloses nothing, so it is printed in full â€” its `Debug` deliberately prints all 32 characters, the opposite of `NameHash`. A domain-separated `PayloadDigest` identifies the *bytes*, so an operator holding a file can hash it and find the matching line, and so the digest survives a daemon restart; being payload-derived it is printed truncated to 16 hex characters, which bounds it to a confirmation oracle rather than an exfiltration channel. The usability cost recorded in the previous revision is closed. Neither identifier is a `Trusted<T>` and neither can reach a prompt, and `log_line()` is the single site that renders a `Handled`, so a new field cannot be printed without someone deciding whether it may be.

## Audit pass (2026-10-20)

A full-workspace review, split across security, CLI/daemon, DSL/policy/types, and Linux-confinement reviewers. Findings confirmed by reading the enforcement point, and now fixed:

- **Write grants could be widened with `..`.** Containment was lexical and ran before canonicalisation, so a request for `/srv/outbox/../etc` passed the check and was then granted `/etc`. Fixed by resolving first and comparing the resolved path. The new test fails against the old check.
- **`agentos run` fell back to local execution on any daemon error, including an authentication refusal.** A client that reached the daemon and was turned away would run the same task in-process, outside the operator's ceiling and potentially twice. `dispatch` now distinguishes `Unreachable` from `Failed`, and only the former falls back. A missing token file is disambiguated by asking whether anything is listening.
- **`Disclosure::approve` did not bind the value to the flagged argument.** The digest was circular: minted from `shown` and verified against `shown`, so it proved only that the token matched itself. It now takes the argument name and refuses a value that is not the one the engine flagged. Mutation-verified.
- **`Quarantined::new` only asserted in debug builds.** A release build would accept an untainted label, producing a value that reads as trusted while carrying untrusted bytes. Now a hard assertion, documented as a programmer-error panic.
- **`is_loopback` used a string prefix**, so `127.0.0.1.example.com` counted as loopback and the endpoint restriction could be routed around with a DNS name. Now parses an `IpAddr` and uses `is_loopback`.
- **The client read timeout was 30 s against a daemon ceiling of 3600 s**, turning legitimate slow tasks into transport failures. Now the ceiling plus a margin.
- **The client panicked on a successful response with no `result`.** Now an error naming the protocol violation.
- **The inbox followed symlinks after admission.** `read_quarantined` and `digest` checked the link's own metadata for size and then read *through* the link; `drain_deferred` promoted whatever was in `deferred/` without checking its type. All three now require a regular file, and the deferred path also enforces the size limit.
- **`agentos service` invoked `sh -c`** with an interpolated command line, contradicting the file's own "no shell" claim. It now splits the fixed `systemctl [--user]` prefix and passes arguments directly.
- **The inbox watcher ran a whole task inline on a current-thread runtime.** Its own doc claimed that being a tokio task meant a slow poll could never block IPC. On `Builder::new_current_thread`, a synchronous call inside a task stops the world, and `handle_entry` runs a model request, tool IO and an audit fsync. Both the poll and the per-entry work now run on `spawn_blocking`, where `DaemonState::run` already puts its work; the comment says what the code does rather than what the runtime would do if it were multi-threaded.
- **`recv_fd` trusted `cmsg_len` and kept only the first descriptor in a message.** A short `SCM_RIGHTS` payload was copied past its end; with the zeroed control buffer that reads as fd `0`, this process's stdin. And the kernel installs *every* descriptor in a message before the receiver runs, so taking the first and returning leaked the rest into the receiver: capabilities nobody agreed to hold, and a descriptor-exhaustion route. It now checks the payload length, collects every descriptor, closes the surplus, and uses `MSG_CMSG_CLOEXEC` rather than a post-hoc `fcntl` that `exec` can race. Verified by sending two descriptors in one message: with the close removed, the test finds the second still open.
- **The fd scrub treated "cannot read `/proc/self/fd`" as "nothing was inherited".** `close_range` is the fast path, but on an old kernel the `/proc` walk is the enforcement, and `scrub_inherited_fds` ignored the walk's failure while `leaked_fd_count` returned zero. A container without `/proc` therefore produced a worker holding the daemon's descriptors, which is exactly the I5 failure the scrub exists to prevent. The walk now returns a result, a malformed `getdents64` record is an error rather than a quiet partial view, and the child refuses to exec on either.
- **The reply drain closed one descriptor and leaked the rest.** `drain_stray_fds` is the function that cleans up descriptors a worker queued after its reply. It read `CMSG_DATA` without checking `cmsg_len`, closed only the first descriptor in the message, ignored `MSG_CTRUNC`, and looped until `EAGAIN` without bounding the rounds. The second descriptor in a message stayed open in the daemon -- a capability nobody asked for -- and `recvmsg` returning `0` at EOF read as "try again". It now bounds and validates every message, closes all of them, treats truncation as a protocol error, and ends at EOF. Tested by sending two descriptors in one message and by closing the sender; the first test reports `1` closed with the surplus loop removed.
- **The inbox read followed the path twice.** `read_quarantined` and `digest` called `symlink_metadata` and then `std::fs::read`, so a link planted between the two was read as its target, and the whole target was allocated before any size check. Both now go through one `O_NOFOLLOW` open and bound the read from the handle they actually opened (`take(MAX + 1)`); a FIFO cannot park the watcher because the open is non-blocking. The test calls the open directly with a symlink, which is the race without the timing.
- **One unusable file in `deferred/` could starve the queue forever.** `drain_deferred` took a rate-limit token before checking whether the entry was a regular file of an acceptable size, so a single oversized or symlinked entry spent every poll's credit and nothing behind it was ever promoted. The check now runs first and the token is taken only for an entry that can actually be admitted.
- **A daemon with a closed standard stream leaked its control socket into the worker.** `socketpair` returns the two lowest free descriptors; if 0, 1 or 2 was closed, one end landed there, and the fd scrub deliberately keeps those numbers. The child then held the parent's end of its own control socket, so the parent's shutdown never produced EOF. `spawn_worker` now refuses a socketpair that used a standard stream.
- **Retiring a dead worker signalled a reaped pid.** `worker_is_dead` reaps with `waitpid(WNOHANG)`, and `reap` then called `terminate`, which sends `SIGKILL` to the same number. That is harmless while the pid is unallocated and a killed bystander if it has been recycled. Retirement now records that the worker was already reaped and only closes the socket.
- **The ABI table claimed unhandled rights were disabled.** Landlock restricts only the rights a ruleset names, so clamping a newer kernel down to V7 leaves rights added later *unrestricted*, not off. The table now says that, and names the seccomp refusal (`connect(2)`) that covers `RESOLVE_UNIX` in practice; the old wording would have let a future right be assumed safe because it was "not enabled".
- **The flood test asserted a directory ordering the filesystem does not define.** It required `payload-5.txt` to be the one deferred; on Linux the iteration order deferred `payload-0.txt` instead, so the test failed only off Windows. It now asserts the property that matters: exactly one overflow payload, under its own name, carrying its own bytes. Found by actually running the suite under WSL rather than assuming it was portable.
- **The model-eval controls could not fail.** One arm was compared against itself, a second row was filled from the wrong arm, and a "declining" row reported the approving measurement. The `--deterministic-only` path also panicked on an unconditional `expect`. All fixed, with a real declining-bounded arm.

- **`Profile::Worker` granted `nanosleep` but not `clock_nanosleep`.** Rust's `std::thread::sleep` calls the latter, so every confined image that slept aborted inside libstd with `ENOSYS` — and the abort was a debug assertion (`left: 38, right: 4`), not a clean error. Found by the cgroup tests, where the probe's `sleep` panicked and the worker looked like it had died for the wrong reason. Sleeping confers no authority, so `clock_nanosleep` is now in the baseline for every profile, with a positive-control probe against both `Filesystem` and `Exec`. Mutation-verified by removing the grant: the probe reports `DENIED errno=38` and the progress assertions never run.
- **cgroup discovery could return a root it could never populate.** Creating and writing a limit cgroup can succeed while migrating a child into it fails with `EPERM`, because cgroup v2 checks the `cgroup.procs` of the cgroup the process is leaving as well as the one it is entering. A plain WSL login shell is in a root-owned `/non-systemd` cgroup and hits exactly this; the old code discovered `user@1000.service`, wrote all four limits, then failed at the first real spawn. Discovery and `validate_root` now check the caller's own `cgroup.procs` and refuse with a message naming `systemd-run --user --scope`, instead of a bare `EPERM`.

- **The live model harness advertised tools the host did not register.** `Planner`'s instruction was corrected to the shipping names (`http.fetch`, `fs.write`), but `agentos-model-eval` still registered the fixture names (`http.get`, `send_email`, `shell`). Every live plan therefore died on its first call with `ToolRejected`, and the arm reported 0 leaks — a number produced by a broken instrument, in the same shape as the old "0% because nothing ran" bug. Fixed by making the instruction a harness parameter (`Planner::with_instruction`, which takes a `&'static str` so runtime data still cannot reach the prompt) and by adding a drift test that the eval instruction advertises exactly the tools the eval host registers. A fresh live run now produces real outcomes, including a leak the model actually attempted (`model/status-injected`).

Recorded rather than changed: **the daemon promotes the task text it receives over the socket to `Trusted` with `Origin::User`** so the planner will accept it. That is a deliberate trust decision (the operator sets the ceiling, and a process that holds the socket and token is already privileged), but it means the I1 claim as written is true of tool output and documents, not of the task string itself. Stated because the invariant table reads stronger than the implementation, and an invariant that is quietly narrower than advertised is the kind of documentation this file exists to avoid.

## Decisions taken

- **No Docker.** WSL2 alone. Docker's own seccomp profile would stack with ours and make blocked-syscall debugging ambiguous.
- **Fail closed over fail open.** An absent policy rule is `Confirm`, never `Allow`. An uninspectable value is denied, never waved through. A descriptor handed over as a name is refused.
- **Untrusted text is never stored in the audit log.** A record is a Controller input; storing attacker prose there would reopen injection one layer over.
- **Confinement happens before the engine starts, in a separate binary.** A model client that opened its socket before `landlock_restrict_self` would be holding a live socket in a process whose `socket(2)` is about to be denied.
- **Workers compile everywhere and refuse at runtime.** A Windows build that needed a cfg in every dependent manifest would push someone toward deleting the dependency instead.
- **Every measurement ships with a control that can make it fail.** The corpus ships with the claim that it defeats a defenceless agent, so a 0% defended rate cannot be obtained by measuring nothing. Three separate bugs in the harness itself were caught this way, including one that reported a *perfect* defence score because an `Rc::try_unwrap` was silently returning an empty execution list.
- **Automatic refusal and human refusal are counted separately.** "0% attack success" is one number covering both "a machine refused this" and "a person was asked and said no"; reporting only the first would let the design claim credit for the user's attention.
- **Harden the invariants before building on them.** `PromptSlot::fill_unchecked_for_test` was `#[doc(hidden)] pub`, so any dependent crate could increment the I1 counter â€” and the number that is supposed to be exactly zero was therefore not a measurement. Building a prompt-assembly path on top of that gate would have produced a green I1 that meant nothing.
